# Plano de ação — tela de detalhes do case study

## Objetivo
Criar uma página/rota `/case-study` que transforme o resumo do portfólio em um case verificável, sem expor informações confidenciais.

## Etapas
1. **Conteúdo**: confirmar nome do produto, período, seu papel, equipe, contexto e quais números podem ser publicados.
2. **Estrutura**: hero com problema e resultado; contexto; fluxo Problema → Solução → Resultado; arquitetura; decisões técnicas; antes/depois; aprendizados.
3. **Evidências**: adicionar screenshots ou mockups anonimizados, diagrama de arquitetura e link para demo/repositório, quando permitido.
4. **Implementação**: criar rota/seção dedicada, componentes responsivos, navegação de retorno e CTA para contato.
5. **SEO e acessibilidade**: title/description próprios, Open Graph, headings semânticos, alt text e navegação por teclado.
6. **Validação**: revisar confidencialidade com a empresa, testar mobile, performance e analytics do CTA.

## Informações necessárias
- URL da demo/repositório/artigo (ou autorização para publicar mockups)
- screenshots/diagrama
- métricas autorizadas e período
- resultado desejado do CTA (link externo, PDF ou rota interna)

Até essas informações chegarem, o botão não deve apontar para uma página vazia nem inventar evidências.
