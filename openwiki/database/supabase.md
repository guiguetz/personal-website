# Supabase e Banco de Dados

## Visão geral

O projeto usa **Supabase** (Postgres) para persistência de dados em duas tabelas:
- **`contact_messages`** — mensagens do formulário de contato.
- **`portfolio_experience`** — experiências profissionais do portfólio (i18n).

O cliente Supabase é inicializado em `src/lib/supabase.ts` e compartilhado entre componentes.

## Cliente Supabase (`src/lib/supabase.ts`)

```ts
import { createClient } from '@supabase/supabase-js';

const url = import.meta.env.VITE_SUPABASE_URL;
const anonKey = import.meta.env.VITE_SUPABASE_ANON_KEY;

export const supabase = url && anonKey ? createClient(url, anonKey) : null;
export const isSupabaseConfigured = Boolean(supabase);
```

- Usa as variáveis de ambiente prefixadas com `VITE_` (expostas no bundle do cliente).
- Se as variáveis não estiverem definidas, `supabase` é `null` e o componente que o usa faz fallback para dados locais.
- **Nunca** expor `SUPABASE_SERVICE_ROLE_KEY` no cliente — ela é usada apenas no servidor (ver [API Routes](../server/api-routes.md)).

## Schema (`supabase/schema.sql`)

### Tabela `contact_messages`

```sql
create table if not exists public.contact_messages (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  email text not null,
  message text not null,
  created_at timestamptz not null default now()
);

alter table public.contact_messages enable row level security;
```

- PK auto-gerada (UUID).
- Timestamp automático de criação.
- Sem campos de status ou resposta (mensagens são write-only no momento).

### Tabela `portfolio_experience`

```sql
create table if not exists public.portfolio_experience (
  id bigint generated by default as identity primary key,
  locale text not null check (locale in ('pt','en')),
  company text not null,
  year text not null,
  current boolean not null default false,
  position text not null,
  period text not null,
  location text not null,
  description text not null,
  tags text[] not null default '{}',
  sort_order integer not null default 0
);

alter table public.portfolio_experience enable row level security;
```

- Suporte i18n: cada experiência tem uma entrada `pt` e outra `en`.
- `sort_order` controla a ordenação de exibição.
- `tags` é um array de tecnologias.
- `current` indica se é o emprego atual.

## RLS (Row Level Security)

```sql
-- Permite que qualquer pessoa (anon) envie mensagens
create policy "public can send contact messages"
  on public.contact_messages for insert to anon with check (true);

-- Permite leitura pública de experiências
create policy "public can read published experience"
  on public.portfolio_experience for select to anon using (true);
```

**Modelo de segurança:**
- `contact_messages`: INSERT público (anon), sem SELECT (só o servidor lê com service role).
- `portfolio_experience`: SELECT público (anon), sem INSERT/UPDATE/DELETE público.

### Corrigindo erros de policy

Dois scripts de correção foram necessários por erros comuns de RLS:

**`fix-contact-policy.sql`** — corrige erro `42501 new row violates row-level security policy`:
- Concedendo `grant insert` explícito ao role `anon`.
- Recriando a policy com `drop` + `create`.

**`fix-contact-policy-v2.sql`** — corrige mismatch entre policy e role:
- Concedendo `grant usage on schema public to anon`.
- Usando `as permissive` e target `to public` (em vez de `to anon`).
- Inclui query de diagnóstico para verificar a policy após execução.

## Seed data (`supabase/seed.sql`)

Popula `portfolio_experience` com 6 empresas × 2 idiomas (12 linhas total):

- Dados hardcoded de cada experiência profissional de Guilherme.
- Tags como arrays PostgreSQL (`array['React','TypeScript','Vite']`).
- Descrições em `$$...$$` (dollar-quoting) para evitar escaping.
- `sort_order` de 1 a 6.
- `truncate table ... restart identity` antes do insert (idempotente).

## Variáveis de ambiente

| Variável | Escopo | Obrigatória | Descrição |
| --- | --- | --- | --- |
| `VITE_SUPABASE_URL` | cliente + servidor | Sim | URL do projeto Supabase |
| `VITE_SUPABASE_ANON_KEY` | cliente + servidor | Sim | Chave anônima (para leitura pública do portfólio) |
| `SUPABASE_SERVICE_ROLE_KEY` | **somente servidor** | Não | Bypassa RLS; usada na rota de contato |
